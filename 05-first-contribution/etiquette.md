# Open Source Etiquette

Every project has its own culture, but respect, clarity, and patience are universal.

## Read first

Look for README, CONTRIBUTING, CODE_OF_CONDUCT, issue templates, and branch or test requirements before asking for help.

## Handle feedback

Treat review comments as information about the project. Ask for clarification when needed and update the change instead of arguing about intent.

## Respect maintainers

Maintainers may be volunteers. Do not demand a timeline, reopen closed discussions without new information, or expect personalized teaching.

## Maintenance note
Check official sources before relying on time-sensitive rules, dates, badge criteria, or program details.
